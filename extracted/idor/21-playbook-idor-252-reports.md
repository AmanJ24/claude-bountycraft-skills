# Bug Bounty Playbook: IDOR, five patterns, escalation ladder, 5-question framework (aggregate)

- **Vuln type / sub-variant:** IDOR / BOLA across HackerOne disclosed reports. Aggregate analysis of 252 reports (ranked by bounty and upvotes, top 30 read in full). The author's thesis: guessing the ID is the easy part; the bug is wherever the server neglects to confirm the requester actually owns that ID. Every IDOR is the intersection of an object reference, an action (read/update/delete) and an authorization check that is missing, wrong or bypassable.
- **Target type:** Business-account APIs, GraphQL APIs (billing, certifications, LLM conversations, ML model registry), account management/destroy endpoints, multi-tenant SaaS, legacy invite/permission pages, unreleased features.
- **Recon signal:** Any endpoint taking an object ID, UUID, slug or GraphQL node ID; sequential or guessable ID ranges; request bodies carrying an email, user ID or owner ID separate from the session; multi-organization products; newly shipped operations spotted by watching JS bundles and GraphQL schema.
- **Root cause:** Server resolves objects by client-supplied reference with no ownership check (patterns 1, 2), validates the wrong thing, e.g. trusts body over session or checks object A while mutating object B (pattern 3), checks tenant membership but not that the object is in the same tenant (pattern 4), or new features launch without inheriting existing authorization (pattern 5).
- **Exploitation steps:** Five patterns, each with its test:
  1. **Pattern 1, sequential or predictable IDs (most common).** PayPal #415081: business account owner adds secondary users from other accounts through a users API endpoint, because the user ID in the body is never tied to the requesting account. Automattic/CrowdSignal #915114: sequential user IDs, an invite-user endpoint with an id param returns the victim's email, and the permissions update step logs you in as the victim (ATO). GitLab #2528293: ML Model Registry used incremental global IDs, so decrementing the number exposed private model registries. Test: swap in an ID from a second account on every ID-taking endpoint.
  2. **Pattern 2, GraphQL node ID substitution.** Shopify #2207248: BillingDocumentDownload and BillDetails operations take a BillingInvoice ID that is incremental; other shops' invoices leak email, address, invoice content and card last four. HackerOne #2122671: CreateOrUpdateHackerCertification mutation lacks ownership check, allowing deletion of any user's certifications. HackerOne #2218334: DestroyLlmConversation mutation in the unreleased Copilot feature deletes any conversation. Test: proxy every GraphQL request, find the id variable, replace with another account's ID; use schema to list every ID-accepting operation.
  3. **Pattern 3, session-object misbinding.** Mozilla #3154983: POST to the account destroy endpoint takes email and authPW in the JSON body; server deletes the body's account rather than the session's. Attacker harvests victim's email and authPW once, then sends the destroy call from their own session with victim values. Starbucks #876300: an alternate site shared database and session cookie with the main Singapore card site, so a session cookie from one worked on the other for ATO. GitHub #3560256 (CVE-2026-3307): authorization checked against the repo in the URL while the action applied to another repo named by an owner_id body param. Test: keep your own auth cookie but swap in a victim-owned identifier in the request body; or call endpoint A with a body that points at object B, to see whether the server acts on the body instead of what it authorized.
  4. **Pattern 4, cross-tenant boundary failures.** Auth verifies you can access your tenant but not that the target object is in it. GitHub #3560256 is one; titles cited: TikTok #984965 (add/update/delete pixel event rules for any tenant), Uber #1063022 (privilege escalation, invitation takeover, editing other businesses' employees), Stripe #1066203 (GraphQL UpdateAtlasApplicationPerson write access). Test: two accounts in two orgs, swap tenant-scoped IDs. Often rated higher since every tenant is affected.
  5. **Pattern 5, new-feature blind spots.** HackerOne #2218334 found by watching JS files for new GraphQL queries (Copilot, not yet live). GitLab #2528293: ML Model Registry feature did not inherit parent project visibility. Test: monitor JS bundles and schema introspection for new operations; they have the least review history.
  6. **Escalation ladder (raise severity by demonstrating the highest rung):** Rung 1 read (Nord Security #751577, payments data of any user, no bounty but 387 upvotes). Rung 2 update (Reddit #1661113 modify any user's links; Yelp #391092 order/book/buy with another user's card). Rung 3 delete (HackerOne #2122671; Pornhub #380410, $1,500, delete photos and albums; deletes rated higher as irreversible). Rung 4 account takeover (CrowdSignal #915114, Starbucks #876300; bounties cross $5,000 here). Rung 5 mass exploitation (PayPal #415081 $10,500 across all business accounts; Shopify #2207248 $5,000 dumping every merchant's billing data).
  7. **5-question testing framework, run per endpoint:** (a) Does it accept an object identifier? (b) Is the identifier sequential or predictable; increment, decrement, or try another account's ID? (c) Does the action go beyond read; test update and delete too? (d) Does the server tie the authenticated session to the object it acts on, or can you keep your cookie and put a victim-owned reference in the body? (e) Is this a new feature; check JS bundles and GraphQL schema for new operations?
  8. Also cited in the sources list: Unikrn #1966006 (user enumeration and PII, $3,000).
- **Bypasses used:** No filter evasion; techniques are ID substitution, body-over-session trust, harvesting victim identifiers from a one-time login, cross-site session reuse, and finding unreleased operations via JS and schema.
- **Impact:** Range from private data read through unauthorized edits and deletes to full account takeover and platform-wide mass data exposure (see ladder).
- **Bounty:** n/a (aggregate). Amounts stated for individual reports: PayPal #415081 $10,500; Shopify #2207248 $5,000; Unikrn #1966006 $3,000; Pornhub #380410 $1,500; GitLab #2528293 $1,160.
- **Lesson / pattern:** For every endpoint, ask whether the server binds the session to the object it acts on, then push the finding up the ladder (read, update, delete, ATO, mass) to show real impact; new features and multi-tenant boundaries are the best hunting ground.
