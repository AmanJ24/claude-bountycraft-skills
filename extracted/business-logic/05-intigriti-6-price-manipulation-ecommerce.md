# Intigriti guide: six common e-commerce price manipulation patterns

- **Vuln type / sub-variant:** methodology/taxonomy
- **Target type:** E-commerce checkout, coupon engines, payment provider integrations
- **Recon signal:** Checkout requests where amount, quantity, currency or coupon fields are sent by the client; third-party payment forms; promo features.
- **Root cause:** Price inputs and discount rules trusted without server-side integrity checks, plus misconfigured payment integrations.
- **Exploitation steps (testable patterns):**
  1. Price tampering: change the amount field in the checkout request to something tiny.
  2. Negative quantity: add a second item with a negative quantity so its value subtracts from the order total. Note it may also zero the shipped item count while still charging.
  3. Decimal quantity: submit fractional quantities and see whether totals and counts diverge.
  4. Integer overflow: send huge price or quantity values so the backend wraps to negative or zero.
  5. Coupons: test repeated redemption (and races on it), expired coupons still accepted, and personal coupons (e.g. birthday) regenerated by editing a profile field. Gift-card purchase with a birthday discount can be recycled for repeated profit.
  6. Currency confusion: switch the currency code (e.g. USD to INR or JPY) while leaving the amount, so 100 units of a weaker currency is paid.
  7. Test cards: look up the payment provider's documented test card numbers and try them in production.
- **Bypasses used:** Parameter tampering, negative/decimal/overflow values, race on coupon redemption, currency swap, test-card acceptance

- **Lesson / pattern:** Frame root causes as formula injection (user input inside the price calculation), security misconfiguration of the payment provider, and logic errors in discount features. Test each input that enters the total.
